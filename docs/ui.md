# UI 規格與開發指引

## 原生桌面與區網 Web（2026-11-14）

實體螢幕改用 `native/` 的 C++／Qt 5 Widgets App，背景 Python 服務維持獨立運行。
桌面圖示、autostart 與 dock 使用 `start-desktop`；安裝時開啟 GNOME 桌面圖示顯示。
主畫面維持 1024×600，影片等比例顯示、底列固定；
設定開啟時影片縮至 768×432，右側 256 px 可捲動。點設定區外或按 Esc 收合，
**不顯示「收合設定」按鈕**。下方 Web 位址由目前網路介面取得，排除相機專用介面；
HTTP port 80 只顯示 `IP`，不顯示 `:80` 或 `http://`；其他埠顯示 `IP:port`，每五秒更新。

原生 App 維持原版配置：右上方由上至下為關閉、縮小、設定三顆 50×50 按鈕，
設定開啟時三顆一起隱藏，點設定區外或 Esc 收合後恢復。影片靠左上，收合時
960×540、展開時 768×432；底列維持固定。圖示為 38 px；追蹤按鈕文字 22 px，
設定按鈕文字 19 px。「近焦／遠焦」並排，「放大／縮小」並排。
俯仰與連續錄影使用 50×30 的開關：未選取為有淺色邊框的藍灰軌道與白色滑塊，
選取後為綠色；停用仍保留可辨識的輪廓。預設跟拍容許區 **40%**，底層 `pan_deadband=0.20`。
原生 App 關閉或縮小不停止背景追蹤與錄影，啟動 App 不自動 ARM。

Web 優先使用 960×540／10 FPS 硬體 H.265＋WebRTC，失敗回退到既有 JPEG。
遠端頁不顯示控制 Jetson 桌面視窗的按鈕。串流比較、安裝與驗證範圍見
[串流與桌面](streaming.md)。以下 HTML/CSS 細節保留作為 Web 版面規格。

### 2026-11-14 更新：自適應 Web 與底部設定

遠端 Web 直接使用瀏覽器可用寬高，不再把整個介面縮放成固定 1024×600 或
1280×800；舊的 `?layout=nano` 網址同樣自適應。影像維持 16:9，辨識框與容許區
依實際影像尺寸繪製。375×812 直向、844×390 橫向與 1920×1080 桌面均需檢查。
只有舊的 `?display=local` Web 相容入口保留固定畫布縮放。

手機 Web 使用動態 viewport 高度（`100dvh`，舊瀏覽器回退到 `100vh`），先保留
64 px 底列，再依剩餘寬高等比例顯示影片。旋轉手機或瀏覽器工具列改變高度時，
影片立即重新計算尺寸，不套用尺寸過渡動畫；影像區限制繪製範圍，底列保持在上層，
確保追蹤與設定按鈕不被影片或設定面板遮住。

Web 的 FPS、錄影、辨識及階段資訊集中於設定最下方的「即時資訊」；底列只保留追蹤與設定按鈕。
使用 Nano 記憶卡錄影時，Web「即時資訊」與機身 App 的錄影設定顯示已用和剩餘容量（GiB）。
數值來自錄影目錄所在檔案系統，剩餘容量以錄影服務可用空間計算。

Web 齒輪放在底部狀態列，設定關閉時不保留右側按鈕欄；原生 App 的三顆按鈕
維持上方所述的右上直排，不套用 Web 版配置。Web 齒輪可開啟與收合設定；
兩種介面的側面板都可捲動且不遮住底部追蹤／停止按鈕。
窄於 700 px 的 Web 以覆蓋式面板保留可讀寬度，較寬視窗則縮小旁邊的影像。
原生桌面仍以 1024×600 為主要尺寸，設定面板不包含底部 56 px 狀態列。

原生桌面與 Web 都提供 PWM「雲台測試」按鈕及每步動作提示，使用相同的
M0／M1 後端與停止／逾時保護。原生視窗失去作用、隱藏、關閉或收合設定時
中止測試；不影響背景服務的正常待命。相機重連提示依診斷狀態更新並於恢復後清除。
下方歷史固定座標表不適用上述自適應 Web／底部設定配置。

## AI 辨識開關（2026-11-19）

原生 App 與 Web 設定提供相同的「AI 辨識」開關，沿用綠色開啟、藍灰關閉的樣式。
服務每次啟動預設關閉；單獨開啟不 ARM、不移動舵機，開始追蹤自動啟用辨識。
追蹤及錄影期間均可關閉 AI，清除舊辨識框與待送自動目標，現行 PWM 保留追蹤啟用狀態，
改以方向鍵手動控制。重新開啟 AI 會停止手動目標，等待新的辨識結果再自動跟拍。
錄影不強制啟用或鎖住 AI；手動／連續錄影依原開關繼續，事件錄影依辨識新鮮度結束。
狀態讀回確認開關；離線、載入中或設定等待時停用。

原生 App 與 Web 在追蹤啟用、AI 關閉且兩軸 PWM 方向／通道已設定時，
可長按鍵盤上下左右持續移動；不受作業系統按鍵重複速度影響，沒有兩秒長按上限。
一次控制一個方向；放開後可再按另一個方向。滑桿、輸入框與選單保留原生方向鍵行為。
放開、Escape、切換視窗／分頁、離頁、STOP 或重新開啟 AI 都停止送出新目標；
後端 0.5 秒未續租也停止，舊請求與延遲回覆不能恢復動作。速度至多 5°/s、
加速度至多 10°/s²；鍵盤俯仰與雲台測試共用 70–110°，水平沿用既有角度限制。
自動俯仰關閉仍可手動上下控制。
開頁與輪詢不 ARM、不發動作；歷史 Pelco-D 方向面板仍為獨立相容入口。

App 與 Web 設定均提供「手動控制速度（°/s）」數字輸入框，預設為設定上限（至多 5）。
有效值輸入即套用，不需 Enter 或失焦；有效範圍為 0.1 至當次後端允許的上限。
編輯中不被狀態輪詢覆寫；快速連續輸入依序送出並以最新值為準，空白／超界不送出。
離線或不支援 PWM 時停用，失敗顯示訊息；速度欄位內的方向鍵只調整數值。
此值在 App／Web 之間共用，服務重啟後恢復預設；完整停止／租約與加速度保護維持。

## 記憶卡檔案瀏覽（2026-11-19）

`/files` 沿用既有區網 Web 服務，提供 Nano 記憶卡的資料夾、檔案大小、修改時間、
剩餘空間、搜尋本頁、分頁與下載。點影片開啟預覽；提供單一 HTTP byte range 以便
瀏覽器讀取／跳播，MKV／H.265 是否可播放仍依瀏覽器支援，不另啟動轉碼程序。
無法播放時保留下載入口。手機與桌面共用自適應清單，入口可返回即時畫面。

資料範圍固定為已掛載的 `/mnt/shore-video`；卡片未掛載時回報不可用，
不退回 eMMC 同名目錄。不跟隨符號連結、不提供寫入／刪除，沿用既有區網存取限制。
開啟檔案頁不 ARM、不啟動錄影或發出硬體命令。這是 Nano 的卡，不代表相機內建儲存空間。

## 目前螢幕與適用範圍

使用者於 **2026-10-31** 確認目前實機螢幕為 **1024×600 像素，橫向**。
這是本專案 kiosk UI 的主要設計與驗收尺寸。1280×800 是保留的相容版面，
不能只在大螢幕看過就宣稱目前實機版面合格。

開發驗收使用 **1024×600 CSS pixel viewport、瀏覽器縮放 100%**；viewport 指網頁
可用區域，不含瀏覽器工具列。實機全螢幕時也需核對可用區域與系統縮放。
未指定螢幕英吋、DPI 或觸控能力；目前操作以滑鼠及鍵盤為基準。

- 實機入口：`/kiosk?display=local&layout=nano`。
- 離線入口：`http://127.0.0.1:18092/kiosk?layout=nano`。
- `layout=nano` 決定 1024×600 版面；`display=local` 選擇本機影像交付模式，兩者用途不同。
- 未帶 `layout=nano` 時仍使用 1280×800 版面，不能以縮小後的舊版面代替主要驗收。

### 選單與視窗互動

- 收合時保留 960×540 影片；展開後影片寬 768、選單寬 256，合計 1024。
  768×432 是 16:9 等比例縮放，不以 `overflow` 遮掉 960 px 影像右側。
  收合時底列延伸至 x=960，右側黑區上下保持直線，不在右下角形成倒 L；
  追蹤按鈕隨底列右移，展開後回到原本 x=612；點追蹤按鈕時等 click 成立才收合，
  避免 pointer-down 就把按鈕移開而吃掉點擊。
- 齒輪與黑色選單使用同一個位移容器；點齒輪展開選單後，隱藏齒輪、縮小與關閉按鈕，且不顯示「控制」標題。
  點控制選單以外的影片、底列或黑色區域即可收合；Escape 也可收合。點選單內不會關閉。
  從控制項收合時把鍵盤焦點交回齒輪。右上角視窗按鈕不視為點擊選單外。
- 「縮小」實際退出 X11 全螢幕，把 kiosk 瀏覽器的內容視窗縮成 **512×300**，
  讓使用者看得到並操作 **Jetson 桌面**；不是在全螢幕裡留下半張介面。
  前端跟隨 viewport 把整個介面縮成 **50%**，不再額外乘一次 0.5。1024×600 畫布變成
  512×300；展開影片變 384×216、選單寬 128，齒輪、縮小／還原與關閉按鈕均變 25×25，字體、間距與底列也同比例縮小。
  再按還原回全螢幕。調整只針對目前使用者的專用 Shore Jetson Chromium profile，
  不改其他程式的視窗；桌面控制不可用時顯示錯誤，不假裝已縮小。
- 「關閉」先顯示確認視窗；取消保留目前畫面，確認後才關閉目前 kiosk 瀏覽器，並非關閉選單。背景服務持續執行；
  此按鈕不停止自動跟拍或錄影；若雲台手動控制已啟用，離頁處理會撤銷該控制並嘗試送 STOP。實機專用 Chromium 啟動器不循環重開視窗。
  一般手動開啟、有多筆歷史紀錄的瀏覽器可能限制程式關閉，此時顯示 Alt+F4 提示。
- Jetson 桌面與 dock 固定 **Shore Jetson** 啟動圖示，關閉 App 後可點擊重開。
  目前由 `deploy/install-desktop.py` 安裝 `start-desktop`，不另啟動一份背景追蹤服務。
  內部 desktop ID `shore-tracker`、`ShoreTracker` WM class 與圖示檔名保留相容。
  `deploy/install-kiosk-launcher.py` 的 Chromium profile 與 `start-kiosk` 為舊 Web kiosk 路徑。

### 雲台手動控制

此方向／速度面板只支援歷史 `pelco_d`。使用者於 2026-11-14 再次確認已換回
CH340G USB-TTL → M0／M1 → 兩顆 180° PWM servo，RS485 雲台已收起；
本面板不是 PWM 手動入口。現行路徑與設定落差見[控制契約](servo-controller.md)。

原獨立雲台測試頁與服務入口已移除，功能統一放在齒輪設定內的「雲台手動控制」。
延續面板黑底、現有字型、青綠操作色與紅色 STOP，256 px 面板內依序放：
「連接雲台／斷開雲台」、「啟用手動／停用手動」、速度 1–63（預設 8）、十字方向及中央停止。
方向按鈕至少 36 px 高，速度與狀態使用 12–13 px；超出 600 px 的設定只在面板內捲動。
影片 768×432、固定底列與既有控制項不改動。

按住移動、放開停止；啟用不移動。每次最多 2 秒、0.4 秒未續租便停止並停用。
方向鍵只在手動控制區有焦點且面板開啟時有效；滑桿方向鍵維持原生調整。
收合面板、Escape、失焦、背景或離頁都撤銷手動 session；ARM 尚在等待回覆時亦同。
前端序號避免延遲回覆重新啟動。開頁、GET／輪詢與單純開啟設定不開手動串口或發動作。
離線預覽、未設定 Pelco-D 或自動跟拍期間禁用手動啟用／方向；STOP 仍是獨立可達的操作。

主程式以互斥串口交接手動與自動控制。手動連接期間先斷開才可開始追蹤；斷開後恢復自動
服務為 DISARMED。手動持有串口顯示「手動控制」，不誤報為控制線中斷。UI 與假串口驗證不代表實機動作驗收。

### 跟拍容許區

現行 PWM 使用既有角度規劃器；一般 TOML 範例仍選停用的 Pelco-D/Moxa，
不能當作現行裝置設定。以下幾何可供兩條程式路徑共用，但 2026 年 10 月 UI 驗證
不代表換回 PWM 後的實體跟拍驗收。設定、要求角度與回授邊界見[控制契約](servo-controller.md)。
Pelco-D 手動面板及[RS485 操作](pelco-d-test.md)保留作歷史相容資料。

「啟用俯仰」使用原生 checkbox（`role="switch"`）呈現 iOS 風格開關：50×30 px、
白色滑塊左右移動，開啟時底色為綠色 `#34c759`，切換動畫 0.1 秒。
預設關閉；後端完成方向校準且支援俯仰通道才可啟用。開頁面不送出設定或馬達指令。
切換經 API 套用並讀回確認；失敗時復原到最後確認的狀態。開關控制真正的俯仰軸自動跟拍，
仍須「開始追蹤」後才有馬達輸出。Pelco 模式下關閉先清掉兩軸待送值並送全停止，
下一個新控制 tick 可繼續水平跟拍，不另送回中指令。
PWM 模式下關閉俯仰只清掉其待送值、不送回中；PWM STOP 是停送位置，不能撤銷已收位置。

**跟拍容許區**只顯示整個區域的比例，不加正負號：原本左右各 4% 顯示為 `8%`。
預設總比例 **40%**，也就是中心兩側各 20%，底層 `pan_deadband = 0.20`（2026-11-14 更新）。
可調總比例為 **10%–80%**（底層 0.05–0.4），API 套用同樣限制。
滑桿每次變更總比例 1%（底層步距 0.005），避免 25% 被瀏覽器吸附到 24% 或 26%。
`pan_deadband` 同時作為水平與已啟用俯仰的容許比例，
靈敏度亦由兩軸共用。比較人物框中心與**來源畫面中心**的偏差，
不是判斷整個人物框是否完全落在區域內。

左右邊界永遠以兩條 **1 px 實線**貫穿影片全高；俯仰啟用後才加上兩條
貫穿影片全寬的上下邊界，構成「井」字。無虛線、色塊或說明小字；無有效影像／狀態時隱藏。
預設左右各為來源寬度 20%，上下各為來源高度 20%。依後端已回報的設定繪製，
配合影片等比例縮放與數位放大的座標轉換；不隨辨識框清除而消失。
960×540 影片的預設線位為 x=288／672、y=162／378；
768×432 時為 x=230.4／537.6、y=129.6／302.4。

Pelco 模式下目標中心進入容許區便清掉該軸方向位元；兩軸皆停時立即送 STOP，
找不到目標或關閉俯仰也送 STOP，不自行回中。速度是級別而非角速度，沒有套用舊角度
加速度限制。兩軸同受影像逾時 DISARM 與 250 ms 控制更新期限保護。
角度欄位保持空值；狀態中的速度是要求級別，不是實測回授。
PWM 角度欄位是要求值／規劃器估計，沒有實際軸角回授。
`ServoConfig` 的自動俯仰預設範圍仍為 85–95°、home 90°；鍵盤俯仰與雲台測試共用 70–110°。
[歷史 M0 紀錄](legacy-m0-controller.md)
保留當時校準，但這些值不是目前組裝已驗收的中立或安全限位，也不適用 RS485。
2026-10-31 已於 Nano 的 1024×600 實際瀏覽器驗證開關 API 讀回、開啟變綠、
960／768 px 影片的 1 px 實線與上下線啟用條件。驗證全程 DISARMED，
最後恢復俯仰關閉；本次未啟動人物自動跟拍。

鏡頭光學放大／縮小按鈕使用放大鏡 `＋`／`−` SVG 圖示，保留「光學放大」與
「光學縮小」的滑鼠提示及可存取名稱；按鈕尺寸、控制動作與追蹤時的禁用規則維持不變。

設定選單不顯示「待命」狀態標籤或「跟拍」標題，移除「跟隨靈敏度」滑桿與
「辨識 FPS、目標、指令角度」三個讀值。原生 App、Web 設定及控制頁均不提供「重新連接相機」按鈕。
調整其他跟拍設定時沿用目前後端已套用的靈敏度，不改變其數值。
不新增自動放大開關，畫面放大滑桿與原有數位取景規則維持原本行為。
設定成功由控制項本身讀回確認，不另保留「已套用」說明字；故障訊息仍會顯示。

### 連線提示與自動恢復

齒輪內的「舵機未連線」指舵機控制串口尚未就緒，不代表已量測舵機本體或軸角。
影像中斷時由系統自動重試，介面保留恢復狀態提示。

相機操作進度使用獨立提示，不與鏡頭／設定回覆共用欄位。每次輪詢依實際恢復狀態
顯示排隊、重連或等待影像；恢復就緒即清除，不需 F5。
服務中斷時改顯示等待服務恢復；持續故障則由
元件狀態警告顯示。影像恢復後立即重新讀取鏡頭功能，不額外等待原先 30 秒的重試間隔。

使用者於 2026-11-14 確認改回 CH340G USB-TTL → M0／M1 → 兩顆 180° PWM 舵機。
`m0_pulse` 模式的串口會自動重試：涵蓋啟動時未插 USB、閒置時拔插及傳送故障。
斷線先取消跟拍，舊 writer 完整關閉後才重開；恢復保持 DISARMED，清除舊目標，
仍須手動按「開始追蹤」。不重啟相機或整個主程式，也不自動回中。
停用的舵機、關閉中的服務及 Pelco-D 手動串口不適用這個 PWM 自動恢復流程。
這些是主機端行為；不證明 TX／RX 接線正確、舵機收到命令或實際到位。

### PWM 雲台測試

齒輪內的 PWM 測試區提供「雲台測試」按鈕；執行中按鈕分兩行顯示目前動作
（置中、左 20°、右 40°、抬頭 20°、低頭 20°）及「停止測試」，點擊即停止送出後續目標。
停止按鈕以紅色顯示；啟動／停止等待回覆時仍可按下停止。
只在 `m0_pulse` 顯示，Pelco-D 的方向控制區則隱藏；兩者不共用動作協定。
通道依本次使用者指定為 **水平 M0、垂直 M1**。依 2026-11-14 放大幅度與 2026-11-19 俯仰減半的要求，
依序要求兩軸置中 90°、左 20°、從當時位置右 40°、抬頭 20°、低頭 20°；
最後水平在中心右側 20°，垂直回中。保留 5°/s 速度及 10°/s² 加速度限制，
因此完整流程約 34 秒，整次最多 60 秒；heartbeat 中斷仍於 1.5 秒停止送出。
要求角度與實際位置仍分開；不顯示固定流程長說明或完成訊息，完成後按鈕恢復「雲台測試」。
Web 不在按鈕下方顯示一般說明小字；停用原因放在按鈕提示，正常動作只顯示於按鈕內。
獨立提示只顯示無法開始、連線／串口異常等原因；開始失敗的後端原因會保留，
不被停止清理或下一次狀態輪詢蓋掉。串口就緒或流程完成均不代表控制板收到命令或舵機到位。

此測試與自動跟拍互斥，不能同時占用串口。測試期間以 heartbeat 維持，收合面板、
Escape、失焦、背景或離頁會停止；遲到的開始回覆不能重新顯示為執行中。
全域停止同樣中止測試；結束後自動恢復串口仍保持待命，不自行開始跟拍。
細節、命令限制與無回授邊界見[控制契約](servo-controller.md#pwm-雲台測試按鈕)。

### 錄影模式

選用 `destination = "camera_sd"` 時，在 Shore Jetson 網頁的設定面板按「開始相機卡錄影」
或「停止相機卡錄影」，網頁將讀回相機的錄影排程開關。排程開啟後，實際寫卡與影片完整性
仍需從相機回放確認。「查詢相機卡」會重新向相機讀取設定，並顯示相機當日最近一段有資料的
定時影片所回報的時間與大小。該片段可能早於這次操作。狀態未知時亦可直接送出停止。
開啟網頁不會開始錄影。
相機卡排程獨立於追蹤和 AI 開關，在 DISARMED 時也可控制；原生 App 僅顯示排程狀態。

儲存至 Nano 時，使用 **連續錄影** iOS 開關，開啟變綠。
預設關閉；設定儲存在資料目錄 `recording-settings.json`，重新開頁或重啟服務後保留。
開頁面、開選單或在 DISARMED 時開啟開關，只改錄影模式，不開始錄影或追蹤。

- 開啟：開始追蹤（ARM 確認）後即錄影，搜尋中、沒有目標、追浪結束及切換目標都不中斷；
  停止追蹤或故障 DISARM 後收尾。連續影片即使未偵測到起乘／衝浪也保留。
- 關閉：沿用事件錄影。穩定辨識追浪後開始試拍，發展成起乘／衝浪才列為有效片段；
  未發展成功且追浪活動消失 2 秒則收尾，僅刪除這次未合格試拍的影片。
  已合格後，連續 5 秒沒有有效起乘／衝浪判定則結束；短暫漏辨識會繼續。
- 追蹤中開啟立即加入連續錄影；關閉則回到事件規則，若事件仍在錄影，不切斷同一段。
  已含連續錄影的片段保留，避免切換模式造成誤刪。影片收尾期間仍保留待處理的錄影需求。

底列錄影標籤只顯示 **未錄影（紅底）／錄影中（綠底）**，整體放大 50%：
Nano 底列所有狀態標籤（FPS、錄影、辨識與錯誤）統一為 21 px 字體、48 px 高度；
1280×800 相容版面統一為 24 px／57 px。FPS 與錄影圓點均為 12 px。
錄影紅點固定每秒閃爍一個週期，亮／暗各約半秒，不縮放、不使用雙拍心跳；
減少動態效果模式停用動畫。
「辨識正常」標籤維持固定位置與綠底，12 px 圓點依**每次新的辨識結果**亮起後
在 120 ms 內淡出；沒有偵測到人物的有效辨識結果同樣閃爍。
後端 `recognition.sequence` 只在接受新模型結果時遞增；預覽影格重複使用同一結果、
狀態輪詢及 FPS 數值更新都不重播動畫。停止、失聯、過期或不同追蹤 run 的結果不顯示；
減少動態效果模式以恆亮圓點取代閃爍。

衝浪階段標籤與其他標籤等高，追蹤時只顯示下列三種狀態：

| 底色 | 文字 | 判定 |
| --- | --- | --- |
| 紅 `#913443` | 尋找中 | 啟動、搜尋及本次事件結束後 |
| 黃 `#f0c75e` | 偵測到追浪 | 搜尋以外，尚未符合事件影片保留條件 |
| 綠 `#1f6f43` | 起乘／衝浪 | 自動跟拍事件進行中，且 `manual_recording.tracking_qualified` 已確認追浪發展成起乘／衝浪 |

綠色直接沿用事件錄影的合格旗標，不另用即時動作分數重算；已合格事件在短暫漏辨識
的寬限期間維持綠色。連續錄影或手動錄影本身不使階段變綠。
事件結束後回到紅色；停止追蹤時隱藏階段。原有故障與指令提示仍可顯示。
準備、收尾、失敗原因與錄影秒數保留在滑鼠提示；連線中斷仍清除過期狀態。
不再顯示手動錄影按鈕。另一條每 600 秒分段的原始串流備份維持獨立，
這個開關控制原本手動按鈕與自動跟拍共用的事件影片。
驗收以假串流／假錄影器確認觸發、保留及收尾；實機只驗證 DISARMED 下的開關讀回。

### 顯示尺寸與效能

預覽來源／Canvas 像素仍為 960×540；768×432 與介面 50% 是顯示縮放，
不會改變相機串流、辨識模型輸入或原始錄影。寬度 960、768 分別是 3840 的 1/4、1/5，
便於保持整數比例；僅選 3840 的因數不代表能提升實際吞吐量。
若未來把預覽管線本身從 960×540 改為 768×432，像素量會少 36%，
但 CPU/GPU、JPEG、傳輸及整體延遲的改善仍需各自量測，不能把 CSS 縮小當作已改善效能。
[Canvas 的顯示尺寸與像素尺寸說明](https://developer.mozilla.org/en-US/docs/Web/HTML/Reference/Elements/canvas#sizing_the_canvas_using_css_versus_html)。

文字與操作優先清楚可讀。沿用現有深色樣式、字型與元件；狀態需有文字，不能只靠顏色。
控制內容超出可用高度時只在面板內捲動，不把整個 UI 縮成難以辨識的大小。
鍵盤焦點要可見，尊重減少動態效果的設定。狀態、錯誤及診斷放在控制區／底列，
避免把操作說明疊在影片上；辨識框與影格的對應規則維持原本行為。

點「開始追蹤」直接送出 ARM，不顯示確認視窗；kiosk 與手機頁行為一致。
關閉瀏覽器仍保留原本的確認視窗。
開頁面、開關選單或調整視窗只改顯示，不得觸發 ARM、錄影、鏡頭或馬達動作。
保持離線、失聯及 DISARMED 的既有操作限制。

## 修改後怎麼驗收

1. 執行 `python3 deploy/preview-web.py`，開啟上方離線入口，設定 1024×600 viewport。
2. 分別查看面板關閉、開啟、再次關閉的畫面。確認影片完整等比例縮放至 768×432、
   選單寬 256、齒輪同步左移、底列固定且開始／停止追蹤未被遮擋；
   沒有整頁捲動、文字被切掉或控制項超出畫面；保留必要截圖作為當次驗證。
   檢查縮小／還原後所有尺寸為 50%／100%、Escape／點擊外部／鍵盤焦點回復。
   在獨立測試視窗驗證關閉按鈕結束瀏覽器後不被自動重開；離線測試不能代替實機關閉驗證。

   `tests/test_kiosk_controls.js`、`tests/test_control_page.js`。檢查失聯／離線狀態，
   並留意瀏覽器 console 錯誤；測試資料不得驅動實體硬體。
4. 共用樣式有改動時再檢查 1280×800 相容版面及受影響的手機頁。
5. 回報測試、畫面檢查與未驗證事項。本機截圖不能代替實機瀏覽器、即時影像或硬體驗收。
