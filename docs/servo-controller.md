# Servo 控制契約：現行 PWM 與歷史 RS485

使用者於 **2026-11-14** 再次確認：RS485 雲台已收起，現行硬體換回
**CH340G USB-TTL → M0／M1 雙通道控制板 → 兩顆 180° PWM servo**。
硬體選擇已確認；本頁不代表已核對目前裝置設定、接線或完成換回後的動作驗收。

## 現行 PWM 通訊與設定

- 程式路徑為 `shore_tracker/servo/pulse_controller.py`、`simple.py`、
  `simple_service.py`、`shore_tracker/config.py`，協定 `m0_pulse`、9600 8N1。
- Jetson 傳 UART ASCII，控制板產生 PWM；兩通道命令為 `#00Pxxxx!` 與
  `#01Pxxxx!`，xxxx 為四位微秒數，不加換行。使用者於本次明確指定
  **水平 M0／00、垂直 M1／01**；實際方向與機械行程仍須現場確認。
- `encode_position()` 的要求值映射為 0°→500 µs、90°→1500 µs、180°→2500 µs。
  這是程式編碼範圍，**不是目前機構的安全行程、量測角度或已知中立**。
  兩顆額定 180° 也不代表裝上機構後可走完整 500–2500 µs。
- 程式要求 `pan_channel`／`tilt_channel` 為不同的 0／1；`ServoConfig`
  預設已改為水平 0、俯仰 1，兩軸方向預設 0（未校準）。這些值不是本次動作驗收。
  水平方向 0 時拒絕開控制服務；俯仰預設關閉，須先校準方向才可啟用。
- 尚無已確認的 ACK、軸角／到位／堵轉回授或控制板 watchdog。
  狀態中的角度是要求值或規劃器估計，不能從成功寫入或開串口推定馬達動作。

## PWM 自動跟拍與停止語意

`TrackingCoordinator` 在 `m0_pulse` 下沿用角度規劃器：以來源畫面目標誤差，
限制要求角速度、加速度與角度範圍；這些都是主機軌跡限制，沒有量測軸位置。
暫失已鎖定人物時保持最後要求角度；無目標的搜尋／收尾決策可要求水平回到
設定的 `home_deg`，俯仰無目標則保持要求角度。預設 90° 不代表目前實體位置；
重新 ARM 不會同步實際軸角。

`SimpleServoClient` 開串口、ARM 本身不送中位或快取目標；收到新控制目標後才輸出。
STOP／DISARM 清除兩軸待送值並停止發送；關閉俯仰只移除其待送值，不送回中。
目標超過 250 ms 未更新或寫入失敗會停送、鎖定當次 client；主 runtime 的 PWM 恢復邏輯
可在釋放舊串口後重建 client，保持 DISARMED，仍須重新開始追蹤，見[架構](architecture.md#pwm-angle-planner)。
影像新鮮度另受 `tracking.frame_stale_seconds`（預設 1.5 秒）保護。
這些不是控制板端的停機保證：servo 仍可能完成最後收到的位置並保持出力，
**STOP 不是取消已收位置或切斷電源**。

主設定頁的「雲台手動控制」方向／1–63 速度面板只接受 `pelco_d`，
不是 PWM 手動控制入口；其放開送 Pelco STOP、0.4 秒租約不能套用為 PWM 停止能力。

## PWM 雲台測試按鈕

齒輪設定內新增「雲台測試」，目前固定使用水平 M0、垂直 M1；設定須與此對照一致，
並有兩軸 ±1 方向設定。跟拍、事件錄影或相機重連期間不能開始。測試先關閉跟拍 writer，
再開啟獨占的測試 writer；全程不 ARM 自動跟拍。GET、開頁與開面板不發動作。

依使用者於 2026-11-14 要求將測試幅度放大四倍，相對位移順序為：
兩軸要求 90° → 左 20° → 右 40° → 抬頭 40° → 低頭 40°。
最後水平在中心右側 20°、垂直回中，不另自動水平回中。按鈕逐段顯示目前要求的動作，
下行固定顯示「停止測試」；不另顯示長說明或完成訊息，完成即恢復「雲台測試」。
首筆是直接要求兩軸 90°；沒有起始位置回授，不能保證實際回中路徑或回中速度。
其後相對段採平滑軌跡，要求速度至多 5°/s、加速度至多 10°/s²；完整流程約 47 秒。
測試 writer 的水平要求值限制為 70–110°、垂直為 50–130°，容納方向 ±1；
不擴大自動俯仰設定的 85–95° 範圍。這些要求值不是已驗收的機械安全行程。

執行中可按同一個紅色按鈕停止後續目標。全域 STOP、收合設定、Escape、失焦、背景或離頁
會撤銷；主機 1.5 秒未收到該頁的有效 heartbeat 也停止，整次最多 60 秒。
逾時 heartbeat、舊開始請求與遲到的回覆不能恢復動作。斷線／傳送失敗會中止並清除
待送目標；完整釋放測試 writer 後才恢復跟拍 writer，保持 DISARMED，不重啟影像。
流程完成不是實際角度、到位或物理停止回授，停止送出不等於斷電。

當次裝置、設定與動作驗收見[接線與驗收](commissioning.md)。本頁未宣稱已部署或實體驗收。

## 歷史 RS485 雲台（已收起）

以下保留 2026-11-06 的設備、讀取測試與 Pelco-D 原始碼說明，僅供日後明確恢復
這台雲台時核對。當時專案名稱為 **RS485 雲台**，品牌與型號未確認；
原廠紙本稱「電動支架雲台」。下列 12 V、Moxa、方向命令及驗證均不適用現行 PWM。

### 當時設備與接線

| 項目 | 歷史 RS485 契約 |
| --- | --- |
| 裝置 | RS485 雲台，水平與俯仰兩軸 |
| 通訊 | RS-485 兩線、Pelco-D、9600 baud、8N1 |
| 地址 | 001，十進位 1，封包地址位元組 `01` |
| 電源 | 使用者獨立提供 12 V；不得接到 Nano GPIO／邏輯電源端 |
| 轉接器 | Moxa UPort 1130，USB → RS-422／RS-485；本專案使用 RS-485 2-wire |
| Moxa 資料端 | **R+＝Data+、R−＝Data−；T+／T−留空，不短接 T 與 R** |
| 裝置識別 | 優先 `/dev/serial/by-id/`；`ttyUSB0`／`ttyUSB1` 編號不是固定身分 |
| 相機 | 2026-11-06 雲台測試沒有安裝／連接相機；鏡頭控制不能當作雲台本體功能 |

Moxa 的 A／B 字母對應為 A＝−、B＝+，其他廠牌可能相反。
雲台端只有 A／B 標示，其正負對應尚未獨立確認，不能由字母猜極性。
使用者將接線由 T 端移至 R 端後，已確認可手動控制轉動；未記錄各條線的
最終 A／B 對應。換線先停止並關閉雲台 12 V 電源。
Nano 原生 3.3 V UART 或 USB-TTL 都不能直接接 RS-485 A／B。
詳細選型與接線見[手動測試](pelco-d-test.md)；尺寸、負載、行程等紙本規格見
[硬體](hardware.md)。

### RS485 指令與可用工具

Pelco-D 一般命令為 7 bytes：`FF 地址 C1 C2 D1 D2 checksum`，
checksum 是地址至 D2 的和取低 8 bits。方向控制為右 `02`、左 `04`、上 `08`、下 `10`；
D1 為水平速度級別，D2 為俯仰速度級別。

- 主設定頁手動控制提供 **1–63** 速度級別，預設 8；不是度／秒，沒有實測速度對照表。
- 地址 1、速度 8 向右：`FF 01 00 02 08 00 0B`。
- 全停止：`FF 01 00 00 00 00 01`。停止要清除方向位元，速度 0 不代表停止。
- 目前未開放水平 Turbo；不能假設本雲台支援規格中的所有擴充命令。
- 相機曝光、對焦、變焦等功能需相機與對應介面支援，不因雲台使用 Pelco-D 就成立。

手動入口統一為主畫面的齒輪設定 →「雲台手動控制」，見[操作文件](pelco-d-test.md)。
原獨立測試頁、啟動模組與靜態檔已移除。開頁及讀狀態不開手動串口或送動作；
離線版面使用 `python3 deploy/preview-web.py`，拒絕硬體控制。

### RS485 軟體與停止語意

主設定頁手動控制啟動為 DISARMED。開頁、連接串口與啟用手動都不發送方向命令；
只有使用者按住方向才發送。放開送 STOP；紅色停止、Escape、空白鍵、失焦與頁面隱藏
會送 STOP 並停用；收合設定面板亦同。每次按住最長 2 秒，主機 0.4 秒沒有新指令也送 STOP 並停用。
手動與自動控制互斥：先停止跟拍再連接手動；手動斷開前不能 ARM。主程式先關閉前一個串口持有者，
再開啟下一個；斷開手動後恢復自動服務仍為 DISARMED。`servo.enabled=false` 僅停用自動輸出，
不禁止使用者在主設定頁明確連接／啟用手動控制以校準方向。

這些是**主機端**保護，雲台端命令 watchdog 尚未確認。
STOP 不是切斷電源，成功寫入不是收件、到位或物理停止回授。
程式當掉、Nano 斷電或通訊線斷開時，主機可能無法送達 STOP。

### 自動跟拍（主程式）

`shore-tracker serve` 已接入 `servo.protocol="pelco_d"`。沿用既有追浪候選 → 起乘鎖定 →
跟拍 → 收尾狀態機及錄影流程，只有已鎖定且仍可見的目標會輸出方向／速度。
搜尋、追浪試拍、目標暫失、收尾與容許區內都停止相應軸；不掃描、不自動回中。

- `VelocityPlanner` 直接使用來源畫面的目標中心誤差，不整合推估角度。
  正速度為右／下，負速度為左／上；畫面方向經 `pan_direction`／`tilt_direction` 校準。
- `pelco_pan_speed`／`pelco_tilt_speed` 是各軸 **1–63 級別上限**，預設 8。
  軸輸出為 0 時清掉該方向位元；兩軸可同封包輸出。未開放 Turbo。
- 既有 `pan_gain_deg` 設定／API 名稱保留相容；Pelco 模式下是無單位靈敏度，45 為基準。
  容許區外速度為 `ceil(上限 × (|誤差|−deadband)/(0.5−deadband) × gain/45)`，
  限制在 1..上限；容許區內為 0。它不是度數，也不是機械角速度。
- 歷史一般範例以 20 Hz 產生／刷新最新命令；影像新鮮度由 `tracking.frame_stale_seconds` 控制，
  預設 1.5 秒。影像逾時會 DISARM 並送 STOP。串口 writer 獨立拒絕超過 **250 ms**
  沒更新的控制目標，嘗試 STOP、鎖定錯誤，需重啟服務。這是兩個不同期限。
- 手動 STOP、故障 DISARM、關閉俯仰與服務正常關閉均實際送出 Pelco STOP。
  關閉俯仰先清掉兩軸待送值並全停；下一個新控制 tick 可恢復水平跟拍。
  寫入失敗（包含不完整寫入）也嘗試 STOP；傳送失敗不能宣稱實體已停止。
- 開串口／ARM 不發移動或回中指令；每次 ARM 使用新的追蹤 run ID，拒絕 STOP／重啟前的
  舊 tick。重新 ARM 必須等新的影像與決策，才會出現方向輸出。
- `/api/status.servo_command` 回報協定與要求的正負速度級別；`position_feedback=false`。
  `metrics.servo_angle_deg`／`tilt_angle_deg` 保持 `null`。診斷列出 Pelco 地址與速度上限，
  不顯示舊 90° home 為本雲台設定。

一般範例（含 Nano）仍保留以下歷史 RS485 設定，不適用現行 PWM：

```toml
[servo]
enabled = false
transport = "serial"
protocol = "pelco_d"
serial_device = "/dev/serial/by-id/usb-Moxa_Technologies_Co.__Ltd._UPort_1130-if00-port0"
serial_baud = 9600
send_hz = 20
pelco_address = 1
pelco_pan_speed = 8
pelco_tilt_speed = 8
pan_gain_deg = 45.0
pan_deadband = 0.125
pan_direction = 0
tilt_enabled = false
tilt_direction = 0
```

若日後明確恢復 RS485，相機裝好並取得當次動作授權後，先依[歷史操作](pelco-d-test.md)確認短按方向與 STOP。
`pan_direction=1` 代表畫面右側目標要求 Pelco right，`-1` 則相反；俯仰 `1` 代表
畫面下側目標要求 Pelco down，`-1` 則相反。0 代表未校準：水平未校準時拒絕開啟控制服務，
俯仰未校準時無法啟用該軸。確認後才在該裝置設定啟用對應軸及 `enabled=true`。
啟用自動跟拍前，先於主設定頁「斷開雲台」；主程式以 exclusive 串口交接，恢復自動服務後仍須手動 ARM。

`m0_pulse` 是現行 PWM 可用的既有路徑；`shore_spotter` 與省略 protocol 的舊設定載入行為保留相容，
不會自動改寫既有裝置設定。RS485 路徑不使用舊角度、脈寬、通道、度／秒或 90° home。
這段 RS485 接入記錄只有當時的來源實作與假串口驗證，不代表已部署或實機跟拍驗收。未取得回授前，不宣稱閉迴路定位、
可靠自動回中、電子限位或碰撞保護。速度上限也不是機械行程保護；主機失電／斷線無法保證 STOP 送達。
